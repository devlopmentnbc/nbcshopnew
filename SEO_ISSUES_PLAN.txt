=====================================================================
GROUP A - Unknown / missing product URLs return 200   (4 issues)
=====================================================================
Cause: ProductDetailsController falls back to the newest product when the
slug is not found, so any URL shows a real product with status 200.

  1. /product-details/x                              -> shows default product
  2. /product-details/zzz-none                       -> shows default product
  3. /product-details/niacinamide-ultra-glow-serum-  -> misspelt slug (trailing
                                                        hyphen) shows a different product
  4. /product-details                                -> no slug, shows default product

FIX:
  - Remove the "newest product" fallback. Unknown slug -> 404 page.
  - /product-details with no slug -> 404.
  - Old ?id=5 / ?slug=abc links -> 301 to /product-details/{real-slug}.
  - Slug with stray trailing/leading hyphens (issue 3) -> trim hyphens, and
    if that matches a real product, 301 to the correct URL; otherwise 404.
  - Replace the ~44 slugless route('product.details') links in
    product-details.blade.php (template demo blocks) with real product
    links, or remove those demo blocks.

=====================================================================
GROUP B - Unknown filter values return 200   (1 issue)
=====================================================================
  5. /shop?category=nonexistent-zz  -> 200 "No Products Found"

FIX:
  - Unknown category, sub-category or brand slug -> 404.
    (Covered automatically by the new clean-URL routes in Group D; the old
    query-string URL with an unknown value will also 404.)

=====================================================================
GROUP C - Trailing-slash duplicate   (1 issue)
=====================================================================
  6. /shop/  -> 200, duplicate of /shop

FIX:
  - Middleware: any GET URL ending in "/" (except the home page) gets a 301
    to the same URL without the slash, keeping the query string.
    (Also check public/.htaccess - Laravel's default rule already does this
    under Apache; it may be missing or the server may be Nginx.)

  - Canonical tag on the new pages = the clean URL (+ ?page=N if > 1).
  - Page title + H1 use the category / brand name.

GROUP E - Listing pages with 0 products   (5 issues)
=====================================================================
   9. ?brand=elithe              - 0 products
  11. ?brand=mydoc               - 0 products
  39. ?sub_category=essential-oil - 0 products
  (12, 21, 26 also have 0 products - handled in Group F)

FIX (automatic, no data changes):
  - Any brand / category / sub-category page with 0 active products gets
    <meta name="robots" content="noindex, follow">.
  - Hide links to empty brands / categories / sub-categories in the header
    menu, categories page and shop sidebar until they have products.
  - They become indexable and visible again by themselves once products
    are added.

GROUP F - Duplicate / misspelt entries (need your decision)   (3 issues)
=====================================================================
  12. ?brand=natures-secret  - 0 products, misspelt duplicate of
                               natures-secrets
  21. ?category=gifts        - 0 products, duplicates Bundles
  26. ?sub_category=anti-acneanti-blemish - 0 products, overlaps Acne-Prone
      (slug is also malformed: "anti-acneanti-blemish")

  + issue 19: Bundles should be served at /gift-sets.

PROPOSED FIX:
  - Add a small "slug redirects" table (old slug -> new target) so removed
    or renamed slugs keep working with a 301 instead of a 404.
  - natures-secret         -> delete the empty brand, 301 to /brands/natures-secrets
  - gifts                  -> delete the empty category, 301 to /gift-sets
  - anti-acneanti-blemish  -> delete the empty sub-category,
                              301 to /skin-types/acne-prone
  - bundles                -> rename the slug to gift-sets
                              (name can stay "Bundles" or become "Gift Sets"),
                              301 bundles -> /gift-sets
  - When an admin changes a slug in future, the old slug is saved to the
    redirect table automatically.

  Delete/rename is done by a one-off migration that ONLY acts if the
  empty entry still has 0 products, so nothing with products is lost.
